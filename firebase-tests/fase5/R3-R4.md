## R3 · Piano Blaze con avvisi di spesa (lo fa l'utente)

**Cosa cambia:** Blaze è "a consumo" ma tiene le stesse quote gratuite di Spark. Con pochi giocatori la spesa
attesa è 0 € o pochi centesimi. **Gli avvisi di spesa avvisano e basta: non bloccano la spesa.**

1. Console Firebase → progetto **tock-v6** → in basso a sinistra "Spark · Senza costi" → **Fai l'upgrade**.
2. Scegli **Blaze** → **Continua**.
3. Account di fatturazione Cloud:
   - se non ne hai uno: **Crea un account di fatturazione**, paese Italia, tipo **Individuale**, carta di credito;
   - se Google propone una prova gratuita con credito: va bene accettarla.
4. Alla domanda sul budget metti **5 €** e conferma → **Acquista** / **Collega**.
5. Avvisi completi (Google Cloud):
   - apri `https://console.cloud.google.com/billing` → il tuo account di fatturazione → **Budget e avvisi** →
     **Crea budget** (se nel punto 4 è già stato creato, aprilo con la ✏️);
   - Nome `Tock`, Progetti: **solo tock-v6**, Servizi: tutti, Crediti: lasciare spuntati;
   - Importo: **Importo specificato**, **5 €**;
   - Soglie: **50 %**, **90 %**, **100 %** sulla spesa effettiva + **100 %** sulla spesa **prevista** (forecast);
   - Notifiche: ✅ "Invia avvisi via email agli amministratori e agli utenti della fatturazione" → **Fine**.
6. (Consigliato) un secondo budget `Tock allarme` da **1 €** con soglia 100 %: il primo segnale arriva prestissimo.
7. Dove controllare i costi:
   - Firebase → ⚙️ → **Utilizzo e fatturazione** → **Dettagli e impostazioni**;
   - Google Cloud → **Fatturazione** → **Report**, filtro progetto `tock-v6`, raggruppato per **Servizio**.
   I servizi che compariranno dopo R4: Cloud Functions / Cloud Run, Cloud Build, Artifact Registry (pochi centesimi
   al massimo). Realtime Database e Authentication restano nelle quote gratuite.

**Ritorno indietro (R3):** prima eliminare la funzione (vedi R4), poi Firebase → Utilizzo e fatturazione →
**Modifica piano** → Spark.

Dopo R3 scrivere a Claude "R3 fatto" (niente numeri della carta, niente screenshot della fatturazione).

## R4 · Caricare la funzione dal computer (Windows), arbitro SPENTO

Una volta sola: installare **Node.js 22 LTS** (`https://nodejs.org`, pulsante LTS) e **Git**
(`https://git-scm.com/download/win`). Poi aprire **PowerShell** (tasto Windows → "PowerShell").

```powershell
# 1. Scaricare il progetto (main aggiornato) in una cartella nuova
cd $HOME
git clone https://github.com/giulianomig-cloud/TockV6.git
cd TockV6

# 2. Strumenti (solo nelle cartelle dei test e della funzione)
cd functions;      npm ci; cd ..
cd firebase-tests; npm ci

# 3. Accesso a Firebase (si apre il browser: stesso account Google del progetto)
npx firebase login

# 4. Controllo PRIMA: la funzione non c'è ancora, l'arbitro è spento
node fase5/verifica-r4.js --prima

# 5. Caricamento: SOLO la funzione arbitro, SOLO sul progetto tock-v6, dalla cartella principale
#    (firebase.json della radice: la funzione deve stare DENTRO la cartella del progetto)
cd ..
.\firebase-tests\node_modules\.bin\firebase deploy --only functions:arbitro --project tock-v6

# 6. Controllo DOPO: funzione presente, arbitro ancora spento
node firebase-tests/fase5/verifica-r4.js
```

Al punto 5:
- prima del caricamento girano da soli il controllo "motore allineato a index.html" e le prove della funzione: se
  una fallisce, **non si carica niente**;
- se chiede di **attivare delle API** (Cloud Functions, Cloud Build, Artifact Registry, Cloud Run, Eventarc):
  rispondere **Y**;
- se chiede **per quanti giorni tenere le immagini** dei container: **1** (costano spazio);
- alla fine deve scrivere `Deploy complete!`. Copiare a Claude solo le ultime righe (niente token).

La funzione usa il database `https://tock-v6-default-rtdb.europe-west1.firebasedatabase.app`
(`functions/.env.tock-v6`, lo stesso indirizzo di `index.html`). Con l'arbitro spento nessun telefono la chiama.

Da **Cloud Shell** (browser, anche dal telefono: `https://shell.cloud.google.com/?show=terminal`) gli stessi passi,
con `/` al posto di `\\` e senza `firebase login` (Cloud Shell usa già l'account Google aperto).

**Ritorno indietro (R4)**, dalla cartella principale:
```powershell
.\firebase-tests\node_modules\.bin\firebase functions:delete arbitro --region europe-west1 --project tock-v6
```

## Classifica: persone e computer (dal server, con l'arbitro)

- A fine partita il server scrive anche `classificaDettaglio/<uid>/persone|computer` = `{ partite, vinte }`.
- **Contro persone** = i due posti avversari sono persone con login (il compagno può essere un computer).
  Tutto il resto conta come **contro computer**.
- `leaderboard/<uid>` resta com'è (totali): la versione "di prima" del gioco la riscrive per intero, quindi i
  conteggi separati stanno in un percorso a parte che i telefoni non possono scrivere (né con 5A né con 5B).
- Con la 5B `classificaDettaglio` è leggibile da tutti. **Come mostrarla nell'app** (linguette, filtro…) va deciso
  con le anteprime: nessuna schermata cambiata finora.

## Pulsante di rilascio: perché non parte senza approvazione

- `rilascio.yml` parte solo a mano, solo da `main`, solo con `PRODUZIONE_ATTIVA = si`; il passaggio che usa la
  chiave è nell'environment `production`, che ha **Required reviewers = l'utente** e accetta solo `main`.
- I segreti sono solo nell'environment (mai fra i segreti del repository): una PR non li riceve.
- `main` è protetto dal ruleset (PR obbligatoria, "Tutti i controlli" verdi, nessuna eccezione): un workflow
  cambiato arriva su `main` solo così.
- Provato il 21/10: due giri si sono fermati in "In attesa" finché l'utente non ha approvato.
- Da sapere: l'approvazione protegge dagli avvii per sbaglio. Chi avesse in mano l'account GitHub dell'utente
  potrebbe approvare lui stesso: per questo la chiave ha **solo** il ruolo Realtime Database Admin.
- Consigliato: in Settings → Environments → production **togliere la spunta** "Allow administrators to bypass
  configured protection rules" (così non esiste nemmeno il pulsante per saltare l'approvazione).
